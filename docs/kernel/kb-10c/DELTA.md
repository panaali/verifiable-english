# kb-10c: user-visible delta

What changed:
- Lean: one new module of theorems, `lean/VE/SoftNorms/ConflictSound.lean`. No existing definition changed and the
  trusted base did not grow (`uv run python tools/trust_map.py --check`: K +0, S +0, trusted +0).
- `ve.soft_route.decide_soft_conflict` is new. It takes `check_conflict`'s arguments and returns its
  `ConflictReport`. Python's witness search and prover only propose; Lean's soft route `soft-conflict` replays the
  witness (CONFLICT) or the certificates (CONFLICT-FREE). A CONFLICT-FREE report's `detail` is Lean's status text
  ("CONFLICT-FREE among rules on the same act, conditional on k coherence premises; ...").
- The three safety-framework harnesses call it in place of `check_conflict(doc.elaborated, ...)`:
  `usecases/anthropic-rsp/run.py` `_conflict`, `usecases/openai-preparedness/run.py` `w1`, and
  `usecases/safety-framework/run.py` `cluster_conflict`.
- `ve.norms.check_conflict` is unchanged.

No keyed answer changed:
- The three harnesses' `--check` runs on the head exit 0. Each compares every result with the committed
  `results.json`, wall time apart. RSP prints `110 / 126`, Preparedness `236 / 239` and FSF `260/262`, the same
  lines the shadow runs printed before the switch. Evidence: `evidence/wall-times.jsonl`, `"mode": "after"`,
  `"rc": 0`. `git status --short` is empty after the runs.
- agent-policy and eligibility do not import `ve.soft_route` (`grep -rn soft_route usecases/agent-policy
  usecases/eligibility`: no match). Their keyed commands exit 0 on the head (`evidence/keys.txt`).
- The shadow paired every `check_conflict` call of the three harnesses with the soft route's answer to the same
  question: 2,039 calls (1,412 distinct questions), 0 differences
  (`docs/usecases/safetyfw/*/kb10-conflict-shadow.json`).

Unchanged on purpose: the harnesses' `route` strings in `results.json` still say "D1 norms@0 W1 check_conflict
...". They are bytes of the frozen keys, and changing them would change a keyed file.
