## What is proved (lean/VE/Route/CodecRoundTrip.lean, namespace VE.Route.Wire)

(1) `decodeClosed_encodeFormula (E φ data) (hCheck : φ.check E [] = true) (hDepth : VE.Surface.formulaDepth φ < VE.Limits.maxDepth) (hNodes : VE.Bridge.formulaNodes φ ≤ VE.Limits.maxNodes) (hData : data = true → usesStringBinder φ = false) : decodeClosed E (encodeFormula φ) data = .ok φ`. Corollary `decodeClosed_encodeFormula_wellFormed`: the same with `hWellFormed : φ.WellFormed E []` (through `VE.check_iff_wellFormed`).

(2) `decodeFormulas_encode (E fs data) (hCheck : ∀ φ ∈ fs, φ.check E [] = true) (hDepth : ∀ φ ∈ fs, formulaDepth φ < maxDepth) (hNodes : (fs.map formulaNodes).foldl (· + ·) 0 ≤ maxNodes) (hData : data = true → ∀ φ ∈ fs, usesStringBinder φ = false) : decodeFormulas E (Json.arr (fs.map encodeFormula).toArray) data = .ok fs`, and `decodeFormulas_encode_wellFormed`. `hNodes` is the list-level limit, in the decoder's own form (`nodeLimit`'s fold); `AstLimit.check` applies the same bound across the list.

Each hypothesis is named after its gate and is the decoder's own bound, not a weaker one:
- `hDepth`: `decodeClosed_refuses_depth` and `decodeFormulas_refuses_depth` (theorems, by `rfl`): the chain of `maxDepth` negations over `⊤` (`depth_negationChain`: its `formulaDepth` is exactly `maxDepth`) is refused with `AstLimit.depthLimit`. Seed S3 shows `<` cannot become `≤`. The route checks depth twice (`AstLimit.walk`, then `decodeFormula`'s fuel), and the fuel is not redundant: `walk` stops silently at the first node Python's decoder rejects for its shape, and `decodeTerm` still reads one such node, a variable index above `2^53 - 1` (`validIndex` refuses it, `getNat?` accepts it). After that node the fuel is the only depth check. `decodeClosed_refuses_depth_past_walk` and `decodeFormulas_refuses_depth_past_walk` (theorems, by `rfl`) refuse `["and", ["unary","p",["var",2^60]], encodeFormula (63 negations over ⊤)]` with the depth diagnostic, and `#guard`s show that `AstLimit.check` passes it and that fuel `maxDepth + 1` decodes it. Sweep of the walk's stop cases against `decodeTerm` and `decodeFormula`: this index is the only node the walk stops at that the decoder still reads; every other stop node is refused by the decoder too.
- `hNodes`, `hCheck`, `hData`: `#guard`s at the end of the module, each breaking that hypothesis only (a 16,383-node conjunction; two 8,191-node formulas, each within the limit, refused together; an unbound variable; a `$string` binder in an environment that declares the sort, refused on a data route and read back on any other; the same on the environment `decodeVocabulary ["data@0"]` builds from a vocabulary with a functional `named(person, $string)` predicate, and, without the flag, the typing gate refusing it first). A node-limit theorem by `rfl` costs about 77 s of kernel evaluation (measured with a scratch file), so it is a `#guard`.

Helpers (all theorems, P by kind): `decodeTerm_encodeTerm`, `decodeFormula_encodeFormula` (any fuel above the depth), `walk_encodeTerm`, `walk_encodeFormula` (AstLimit.walk counts exactly `formulaNodes` and reports no limit), `foldlM_walk_encode`, `astLimit_check_encode`, `mapM_decodeFormula_encode`, and one-step unfoldings of `AstLimit.walk` proved by `rfl` (`walk_var`, `walk_const`, `walk_leafNode`, `walk_unaryAtom`, `walk_pairAtom`, `walk_unaryNode`, `walk_binaryNode`, `node_step`, `term_step`, `walk_bind`, `ok_bind`, `foldl_add`, `encodeFormula_arr`). No definitions were added. The module builds in about 3 s. A first version took 70 s because simp reduced `walk`'s and `decodeFormula`'s matches; the `rfl` unfoldings replaced that.

## Notes for the DRI

- Depth is checked twice on the route (AstLimit.walk, then decodeFormula's fuel), with one diagnostic. Neither check is redundant: the walk's check refuses depth before decoding (Python's order), and the fuel is the only check after a node the walk stops at but the decoder reads (a variable index above `2^53 - 1`). `decodeClosed_refuses_depth` pins the walk's bound and `decodeClosed_refuses_depth_past_walk` pins the fuel's (S2a). For KB-4's "one formula codec", merging the two would need the walk and the decoder to agree on which nodes are well-shaped (here `validIndex` against `getNat?`). Python's `_Decoder` refuses that index at the node, with `UnboundVariable` "Invalid variable index" (ve/ast.py:505-507), before any depth check. So on the review's input Python's decoder and Lean's route give different diagnostics. That difference is pre-existing (no decoder is edited here) and is left for KB-4.
- FOLLOW-UP (review C note, not fixed here): the module docstring of lean/VE/Route/Wire.lean:21-23 says `$string` is never in an environment's sorts. That has been false since flags were added (:43-47), and it is the text the first report's `hData` claim relied on. This item edits no existing Lean source. The fix is one docstring sentence in a heavily shared file, for the next item that edits Wire.lean. The `#guard`s at CodecRoundTrip.lean:460-489 now pin the true behaviour mechanically.
- A node-limit refusal theorem by `rfl` costs about 77 s of kernel evaluation, so it is a `#guard`. A general converse (`formulaNodes φ > maxNodes → decodeClosed … = .error nodeLimit` for well-typed φ) would need the walk's overflow case and the fact that a closed formula's variable indices are below 2^53 (from `hCheck`). It is not proved here.
