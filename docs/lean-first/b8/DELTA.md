## Fault order and texts of malformed reports documents

`ve/reports.py` keeps no check of its own: the record, duplicate, limit and profile checks that a first fix had moved into `ve/reports_preflight.py` (outside `tools/relay_lint.py`'s list) are deleted, and Lean names every fault. `lean/VE/Attribution/Preflight.lean` (`check`) walks the raw document in the pre-batch Python's order with its texts (LEAN-FIRST-PLAN DRI answer 3: Python's better texts are ported into Lean): profile, then contexts and assessments as records (`must be a list`, limit, `record`, duplicate), duplicate bridges and scoped checks, their limits, reading choices, each context (`InvalidInput: context <c>`, `ContextTense`), each assessment (`needs decided_by`, `UnknownSymbol: evidence context`, `InvalidInput: assessment <a>`, then its formulas), each unit and its content tree, each scoped check (`InvalidInput: scoped`, paths, `ScopedTarget`, `ScopedEnvironment`) and each bridge (`InvalidInput: bridge`, `BridgeTarget`, `BridgeKindMismatch`); the decoder's `firstFailure` names the rest (metadata, generated predicates) in the same order. It only rejects. A formula's verdict stays the decoder's; its text is Python's decoder text (ported) or typing text (`Service.TypingDiagnostic`). JSON `null` reaches Lean as positions (`nulls`, written by `ve/reports_route.py`), so `null` is absence exactly where Python's `None` was.

`tools/relay_lint.py` now also lints every `ve` module that only relayed modules import (`helpers`), so a check cannot leave the lint by moving into a module of its own (`test_a_check_moved_into_its_own_module_is_still_linted`).
