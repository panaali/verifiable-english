# Lean-first batch 16b: the document switch

Base `8350e55f` (main, with 16a merged); branch `lean-first/b16b`. `ve document check`, `load_document`,
`coverage` and `render_document` now ask Lean's `document` mode (16a) first for every `ve-document@1` text. Lean's
answer is final: its rejection is raised verbatim, and its acceptance gives the unit spans, statuses, parents, checked
content, meaning ids, document and source ids and the coverage, from which Python builds the document
(`ve/document.py` `_lean_document`) after binding the answer to the request. Python's own loader runs only for the
answers listed under *Retained* below. [LEDGER.md](LEDGER.md) maps each wrapper decision to its owner.

## Deviation: the planned deletion is blocked, not done

The plan's row 16b deletes about 900 lines of `document.py` (`_load_document`, `coverage`, `_report`). This batch
deletes none of them, because 16a's mode still answers `CheckerUnavailable` for most documents, and deleting
Python's path for those would remove a capability, which the plan forbids without a DRI acceptance by name (section
5, "port first, then delete"). Measured at the head (`evidence/share.json`): Lean decides 2 of the 393 pilot
documents, none of the 1,250 rights or 1,010 norm-defaults corpus documents, and 773 of the 1,816 document-corpus
texts. Python's wrapper code is shared by every retained profile, so no part of it is reached only by documents
Lean now owns. What the batch did instead:

- every document the mode owns is decided by Lean alone (`test_owned_documents_are_decided_by_lean` runs with
  Python's loader refused); for those, Python's wrapper checks, status inference, coverage, identities, graph
  label checks and narrowing check do not run;
- the retained path is a closed list: only a row the mode marks as undecided reaches it, never a service failure
  (`test_a_service_failure_is_never_answered_by_python`);
- two 16a bugs the switch exposed are fixed in Lean (below).

**Proposed batch 16c** (DRI): compose in the mode the routes the table below names. The largest single item is the
restricted JSON reader's refusal of `null`: readings without content (`"content": null`) in the use-case documents,
and `null` predicates and deciders in the rights corpus, keep 982 document-corpus texts, 782 rights documents and
32 pilots on Python's path whatever their profile. After that, the profile routes (norm-defaults 315 pilots,
rights, readings@1, soft norms) carry the pilots. Python's loader, `coverage` and `_report` wrapper are deleted when
the table is empty.

## Lean changes

- `document` rows carry each unit's checked `content` and `meaning_id` (schema `document.json#/$defs/unit`,
  `unit_fits` re-proved), so Python reads identities from Lean (rule 5).
- A case may say `"admit": false`: `load_document` alone, without `_report`'s claim-graph part, which
  `check_document` adds. Without it Python's `ve document render` and `coverage` would reject documents whose graph
  fails admission, which they accept today.
- **16a bug, fixed:** a document with `senses` was rejected as "unknown document metadata" (the shared metadata
  table predates RD-8); it is now `CheckerUnavailable` (the senses route reads it).
- **16a bug, fixed:** a plain claim graph was admitted by calling `runAdmit` directly, which skips the route's
  gates; a `definitions@0` document with a graph was then admitted node by node where the route defers it. The mode
  now asks `Route.Run.dispatch` for the admission case, as `admit_document` does. Found by
  `tests/test_document.py::test_definition_kind_uses_pinned_environment_and_graph_gap_is_explicit`.

No theorem was added, removed or restated (`tools/lean_statements.py`: 0/0/0); `lean/audit.py` passes.
