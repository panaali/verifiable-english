# Batch 14b behaviour delta

The saved [1,350-record A/B comparison](evidence/corpus-ab.json) covers 150 generated documents, 50 per closure, core and order family, across premises, certificate replay, proof search, absent packages, no evidence and three finite models per document. The two recordings contain the same inputs, and all 1,350 answers are identical. The [retained-route comparison](evidence/fallback-compare.json) runs the same operations at the head with the Lean route switched off: all 1,350 answers are identical to the base too. The [Stage-0 probe](evidence/probe-compare.json) has 18,870 identical base/head rows; the other section 5.1 corpora and pilot outcomes are listed in the report.

## Corpus documents: no unsigned changes

Batch 14b changes no corpus answer outside the standing rulings below. Corpus document indices 13, 28, 64 and 94 have a well-typed n-ary atom inside a lower regulated predicate's outcome. The base did not substitute that atom's variables when it expanded the outcome for conflict search, so the expansion is ill-typed and the base raises `TypeMismatch`. An earlier head substituted them, first on both routes (review F2) and then on the Lean family route only. That turned 16 base rejections into answers (`conflict-prove` and `conflict-model-0/1/2` for each document), which no standing ruling signs (review F3).

The head now admits each conflict target by the base's expansion on both routes, which leaves n-ary atoms unsubstituted, so those 16 operations raise the base's `TypeMismatch` again. Substituting n-ary atoms is n-ary scope, which belongs to batch 14c. It needs a DRI signature there as a rejection-to-answer change. `test_lean_family_route_answers_as_the_retained_python_route` checks that every conflict operation (finite model, proof search, missing packages and witness check) answers the same on the Lean family route and the retained Python route. It runs on closure, core and order documents, first-order or not, and on document 13's n-ary shape. `test_retained_python_route_keeps_the_base_nary_expansion` pins the base `TypeMismatch` on both routes. The seeded faults `nary_substitution` and `lean_route_answer_drift` in `mutants.py` are caught by these two tests.

## Needs a DRI signature: n-ary capture documents (review F5)

The base's expansion also leaves an n-ary atom unsubstituted when its arguments share a sort. Then the citing rule's binders capture the atom's variables, and the formula still type-checks but means something else. At the base such documents were on the retained Python route, which searched and proved that captured formula. At the head they are on the Lean family route, which checks Lean's regenerated targets with the atom substituted. Before this fix the head still searched the captured formula, so Python proposed witnesses that Lean refuted, and the model check raised `CheckerUnavailable` (review F5).

The Lean route's untrusted witness search, prover and CONFLICT situation now use the substituted targets. `test_lean_route_generators_search_the_targets_lean_regenerates` checks that these are exactly the targets Lean's `norms-elaborate` regenerates. The base's expansion is still the admission check, so the F3 `TypeMismatch` rejections above are unchanged, and the corpus comparisons above were re-recorded at this fix with zero changes. The [capture-document record](evidence/capture-delta.json) (`capture_delta.py`) runs every conflict operation and witness check on 20 such documents with four models each. It compares the Lean family route with the retained Python route, which answers as the base did. 11 of the 280 records differ, and no standing ruling covers them:

* Nine finite-model checks change from the base's CONFLICT to UNKNOWN. In each, Lean's own witness check refutes the base's conflict at every tuple (`test_lean_route_model_check_answers_as_lean_checks_each_candidate`).
* One proof search changes from UNKNOWN to CONFLICT-FREE (`same-exists-proved`). Lean's target is unsatisfiable, and Lean replays the prover's certificates (`test_lean_route_proof_search_proves_the_targets_lean_replays`).
* One CONFLICT situation no longer names `rule cited releases`, a rule that is selected only under the captured expansion. The status, target and tuple stay the same (`test_lean_route_situation_names_the_rules_selected_by_leans_targets`).

The alternative is to answer as the base did. For the nine model checks that would mean reporting a conflict that Lean refutes, which presents an unchecked result as checked. The DRI may sign these changes, or move capture documents back to the retained route until batch 14c. `check_witness` stays retained Python on both routes, so its answers on these documents are the base's: it still confirms the nine refuted witnesses. Batch 14c owns that, together with n-ary scope. The evidence manifest binds the 11 listed records, so the list cannot grow unnoticed. The same Lean-target class also covers deferred review F6: complete certificate packages that change base UNKNOWN to CONFLICT-FREE.
