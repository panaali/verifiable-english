## No unsigned changes

Batch 14b changes no answer outside the standing rulings below. Corpus document indices 13, 28, 64 and 94 have a well-typed n-ary atom inside a lower regulated predicate's outcome. The base did not substitute that atom's variables when it expanded the outcome for conflict search, so the expansion is ill-typed and the base raises `TypeMismatch`. An earlier head substituted them, first on both routes (review F2) and then on the Lean family route only. That turned 16 base rejections into answers (`conflict-prove` and `conflict-model-0/1/2` for each document), which no standing ruling signs (review F3).

The head now leaves n-ary atoms as the base did on both routes, so those 16 operations raise the base's `TypeMismatch` again. Substituting n-ary atoms is n-ary scope, which belongs to batch 14c. It needs a DRI signature there as a rejection-to-answer change. `test_lean_family_route_answers_as_the_retained_python_route` checks that every conflict operation (finite model, proof search, missing packages and witness check) answers the same on the Lean family route and the retained Python route. It runs on closure, core and order documents, first-order or not, and on document 13's n-ary shape. `test_retained_python_route_keeps_the_base_nary_expansion` pins the base `TypeMismatch` on both routes. The seeded faults `nary_substitution` and `lean_route_answer_drift` in `mutants.py` are caught by these two tests.
