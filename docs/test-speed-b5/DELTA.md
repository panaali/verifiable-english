# Test-speed B5: user-visible deltas

Every delta is in the developer tools; no VE verdict, diagnostic, wire field, theorem statement or accepted input changes. No standing ruling in DRI-RULINGS.md (R1 to R11) covers developer-tool behaviour, so each row says what authorizes it.

| Id | Delta | Authorization | Test |
|---|---|---|---|
| D1 | `select_tests.py --run` starts the test files that failed last time, then the changed ones, then the rest, and prints its order. The selection is unchanged (a permutation). | The DRI's B5 task instruction ("agents run last-failed and changed tests first"). | `tests/test_test_order.py::test_the_order_is_a_permutation_of_the_selection`, `test_the_last_failed_then_the_changed_then_the_rest` |
| D2 | `select_tests.py --run` stops after 5 failed tests by default (`--maxfail N`, `0` for all), says `STOPPED EARLY`, exits 1, and leaves the files it did not run to the static graph. | The DRI's B5 task instruction ("with --maxfail"). The default of 5 is this batch's choice. | `test_a_recorded_run_stops_after_maxfail_failures`, `test_stopping_kills_the_running_units`, `test_a_plain_run_stops_after_maxfail_and_keeps_what_it_did_not_run` |
| D3 | The gate retries a failed quarantined test once, alone and serially. If it passes there, the gate does not fail on it, and the record keeps both outcomes (`quarantine.retried`). | The B5 instruction (a tracked quarantine; quarantined tests still run and block the nightly). The retry-alone condition is this batch's, and it is stricter than not blocking at all. It lets a test that fails under load past the gate for up to 7 days, so the DRI should confirm it at review. DRI signature: requested. | `tests/test_gate_quarantine.py` (fails alone, no result, another failure, expiry boundaries, malformed file) |
| D4 | New gate option `--no-quarantine` for the nightly, and a new record field `quarantine` (enabled, day, active, expired, retried). Nothing is removed or renamed. | Added information, within the B5 instruction. | `test_the_nightly_retries_nothing`, `test_a_quarantined_failure_that_passes_alone_does_not_fail_the_gate` |
| D5 | The gate's pytest refuses `--maxfail`, `-x`, `--exitfirst`, `--sw` and `--stepwise-skip` with a usage error. | The B5 instruction ("gates never stop early"). | `test_the_gates_plugin_refuses_to_stop_early`, `test_the_gates_pytest_runs_every_test_whatever_the_project_or_shell_asks` |
