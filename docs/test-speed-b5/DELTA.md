# Test-speed B5: user-visible deltas

Every delta is in the developer tools; no VE verdict, diagnostic, wire field, theorem statement or accepted input changes. The standing rulings in DRI-RULINGS.md cover D3 (R13); every other row says what authorizes it.

| Id | Delta | Authorization | Test |
|---|---|---|---|
| D1 | `select_tests.py --run` starts the test files that failed last time, then the changed ones, then the rest, and prints its order. The selection is unchanged (a permutation). | The DRI's B5 task instruction ("agents run last-failed and changed tests first"). | `tests/test_run_order.py::test_the_order_is_a_permutation_of_the_selection`, `test_the_last_failed_then_the_changed_then_the_rest` |
| D2 | `select_tests.py --run` stops after 5 failed tests outside the quarantine by default (`--maxfail N`, `0` for all), says `STOPPED EARLY`, exits 1, and leaves the files it did not run to the static graph. The count is the exit status's own: pytest gets `tools/maxfail_pytest.py` (`--ve-maxfail`, `--ve-quarantined`), never its own `--maxfail`, in the one-process run and in each recorded file (review F1). | The DRI's B5 task instruction ("with --maxfail"). The default of 5 is this batch's choice. | `test_a_recorded_run_stops_after_maxfail_failures`, `test_stopping_kills_the_running_units`, `test_a_plain_run_stops_after_maxfail_and_keeps_what_it_did_not_run`, `test_a_quarantined_failure_never_stops_a_plain_run`, `test_a_recorded_unit_runs_past_its_quarantined_failure`, `test_no_run_path_passes_pytests_own_stop_options`, `test_the_stop_plugin_refuses_pytests_own_maxfail` |
| D3 | The gate retries a failed quarantined test once, alone and serially, on the same commit. If it passes there, the gate does not fail on it, and the record names it and keeps both outcomes (`quarantine.retried`); if the retry fails, or gives no result, the gate fails. | SIGNED by standing ruling R13 (DRI-RULINGS.md): a serial rerun of the same commit, the record names the retried test, and a failing rerun still blocks. | `tests/test_gate_quarantine.py::test_a_quarantined_failure_that_passes_alone_does_not_fail_the_gate`, `test_a_quarantined_failure_that_fails_alone_fails_the_gate`, and the no-result, other-failure, expiry and malformed-file tests there |
| D4 | New gate option `--no-quarantine` for the nightly, and a new record field `quarantine` (enabled, day, active, expired, retried). Nothing is removed or renamed. | Added information, within the B5 instruction. | `test_the_nightly_retries_nothing`, `test_a_quarantined_failure_that_passes_alone_does_not_fail_the_gate` |
| D5 | The gate's pytest refuses `--maxfail`, `-x`, `--exitfirst`, `--sw` and `--stepwise-skip` with a usage error. | The B5 instruction ("gates never stop early"). | `test_the_gates_plugin_refuses_to_stop_early`, `test_the_gates_pytest_runs_every_test_whatever_the_project_or_shell_asks` |
| D6 | `select_tests.py --full --run` never stops early and applies no quarantine; `--full` with `--maxfail N > 0` is a usage error (review F5). | The B5 instruction (quarantined tests still block the full suite) and docs/ARCHITECTURE-LAYERS.md, which names `--full --run` as the full suite before a green tag. | `test_a_full_run_counts_quarantined_failures_and_never_stops`, `test_the_maxfail_options` |
| D7 | Interrupting, terminating or hanging up a recorded run (`select_tests.py --run`, `test_map.py record` or `update`), or any failure inside it, kills the test files it is running before it exits (review F2). | Restores the merge base's behaviour, where the files were in the run's own process group. | `test_killing_a_recorded_run_kills_its_units[SIGTERM, SIGINT, SIGHUP]`, `test_a_failing_recorded_run_kills_its_other_units` |
