# cmp-s2b: the rights case of `superpose_faithful` needs a typing hypothesis (question to the DRI)

Item cmp-s2b (composition S2b). Plan: docs/spec/composition-PLAN.md S2 (the Lean block, `superpose_faithful`), 2.3
(quiescence), 2.6 (the fixed bar), fixture F21; composition-S2-PLAN.md edit 1.

## The statement as approved

```lean
theorem superpose_faithful (D) (h : WellFormedDoc D = true) (hs : superposable D = true) (c) (hc : Compatible D c)
    (S : VE.Structure) (he : Encodes D c S) (hq : Sat S (choicePremises D))
    (r : Regulated) (hr : r ∈ (correlate (choiceDoc D c).1).T.regulated) (vs : List S.Carrier) :
  ValueSoft (correlate (sup D).1) r S vs = ValueSoft (correlate (choiceDoc D c).1) r (pull (nameMap D c) S) vs
```

`vs` is any tuple: it is not required to lie in `r.sorts`, and `VE.Structure` does not require a relation to hold
only on well-sorted tuples (lean/VE/Semantics.lean: `relation : String → List Carrier → Prop`).

## Why the rights case is false as stated (F21's fixed bar)

F21's shape: frame regulates the permission `m` (unary over sort `person`, allowed by default) and a claim
predicate; set `rs` = {claim line on another predicate, liberty line on `m`}; a fixed bar unit, reading `rule`.

* `sup D` has the bar node `¬m(x) if aimed_m(x)`, strict, hard, generated by `correlate` unchanged
  (lean/VE/Rights/Correlate.lean `barNode`: guard `aimedF D m` only, no carve-out, no choice atom), as edit 1
  requires ("the fixed bar's implementation kept intact").
* Quiescence puts `∀x:person. aimed_m(x) → χ_liberty` into `Choice_D` (plan 2.3: `∀x̄. g(x̄) → ⋁ χ(owners(g))`).
  A VE formula quantifies only over a sort's domain, so the premise says nothing about an element outside `person`.
* Take `c` = the claim choice and `S` with the claim's bits at `ve__here`, every other relation empty except
  `aimed_m(e)` for one element `e` that is in no domain. `he` holds; `hq` holds (the quiescence premise is vacuous
  at `e`; every other premise holds); `m ∈ regulated`. At `vs = [e]` the bar node is live in `sup D` and has no
  children, so `sup D` decides `m` false at `[e]`: `ValueSoft … = some false`. The claim choice's document has no
  node on `m` (no liberty, so no bar node): `ValueSoft … = some true` (allowed by default). The two sides differ.

The same holds for every rights predicate that only quiescence silences, not only `aimed`: an unchosen candidate
limitation `L'` in scope of a fixed line puts `lim_{L',a}` into that line's packed carve-out in `sup D`, and at an
ill-sorted tuple quiescence cannot empty it. S2a never needed this: an unchosen soft rule is dead through its
guard's choice atom, a closed formula at `ve__here`, which holds or fails independently of `vs`.

At well-sorted tuples the statement is what 2.3 argues: quiescence empties `aimed_m` and `lim_{L',a}` at every
`vs` with `VE.TupleTyped S r.sorts vs`.

## The question

May the rights case of `superpose_faithful` add the hypothesis `(ht : VE.TupleTyped S r.sorts vs)`?

* (A), recommended: add `ht` to `superpose_faithful` (one statement for both chains; S2a's proof ignores it). Every
  corollary reads `ValueSoft` only at well-sorted tuples (`holdsSoft`/`IntendedSoftAt` quantify over
  `TupleTyped S r.sorts vs`), so `base_down`, `base_up`, `superpose_conflict_free`, `superpose_all` and
  `superpose_countermodel` keep their approved statements.
* (B): keep `vs` free and add a hypothesis that `S` is sorted (every relation holds only on well-sorted tuples).
  This is stronger than (A) and adds a new predicate on structures.
* (C): change the construction instead (gate the bar node or the packed carve-out in `sup D`). Edit 1 forbids this
  for the bar ("the fixed bar's implementation kept intact"), and it would change `correlate`.
