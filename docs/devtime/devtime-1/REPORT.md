## Where each column comes from (nothing typed in)

- **Modes:** `MODES`, imported from `ve/backends/service_schema.py`.
- **Schema:** `ve/backends/lean_service_schema/<mode>.json`, if the file exists.
- **Lean:** `lean/statements.txt`, which `tools/lean_statements.py` generates from the compiled environment. `VE.Service.runMode` dispatches every mode, and each audited equation `VE.Service.runMode_<ctor>` has a `-- uses name@Module` line naming the implementing constants and their modules. The tool drops the dispatch's own module and maps modules to files through `source_graph`. A constructor is matched to a mode when they are equal once case, `-` and `.` are ignored, and the match must be unique. The other two candidate sources fall short:
  - `ve/assurance-manifest.json` bindings name a `ve_service` dispatch file for only 8 of the 32 modes. `route` prints them alongside.
  - `lean/declarations.txt` lists every constant, but not which one a mode runs.
- **Python relays:** found with the `source_graph` import graph plus Python's `ast` (no regex).
  - Relay entries are the module-level functions whose first parameter is `mode`, in the service client, the files it imports, and the files that import it. Today these are `relay.rows`, `relay.decide`, `relay.decide_once`, `relay.answer`, `service_schema.check_row`, `service_schema.check_response` and `lean_service.deadline`.
  - A relay is a `ve/` or `ve_experiments/` file that calls one of those entries, imported from its defining file, with the mode as a literal or a module-level string constant.
- **Tests:** `tools/select_tests.py`'s rule, called through its own functions (review F1). The coverage map (`tools/test_map.find_map`, or `$VE_TESTMAP`) answers only for the test files it recorded whose run cannot have changed since: its drift check `select_tests.uncertain_since` up to HEAD, plus `uncertain_units` for the working tree. The static import graph answers for every other test file, and for all of them when the map vouches for none, when its commit is not in the repository, or with `--static`. A route's tests are the test files that ran a function holding a relay call (map) or import a relay file (static). A file's tests are those `select_tests` picks for an edit to it, without its smoke tests.
- **`file`:** the layer comes from `layer_policy.source_layer`. The generator comes from `tools/regen_generated.py --owner` when that tool exists and offers the option. It reached main with `infra/eff-merge`, so `file ve/backends/lean_service_schema/discourse.json` now prints `generator: response-schemas` with no change to `repo_map.py`. AGENTS.md's generated-files section now points to `tools/regen_generated.py` (`--list`, `--owner`, `--check`, `--write`, `--resolve`) instead of listing generators by hand.
