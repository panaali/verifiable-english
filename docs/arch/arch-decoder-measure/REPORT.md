## 2. What a switch would add (deliverable 2)

### 2.0 The switch as first framed cannot exist (proved)

The framing "Core's decoder, then an atom-free check" means that some `check` reads Core's answer. No such `check` can
equal closure's decoder on every input. `switch.lean` part A proves this by `decide` (no `sorry`):

```lean
theorem no_check_after_core :
    ¬ ∃ check : Except String VE.Core.Tableau.Trace → Except String VE.Closure.Tableau.Trace,
      ∀ fuel j, check (VE.Core.Wire.decodeTrace fuel j) = VE.CertificateWire.decodeClosureTrace fuel j
```

The witness is a fault-order case. Take a trace whose first child has an `atom` invariant and whose second child has
an unknown rule. Core answers `unknown tableau rule` both for it and for the bad node alone. Closure answers
`invalid indexed formula` for the first and `unknown tableau rule` for the second. Even a single node shows a different
text: `binaryAtom_texts` gives Core `Atom terms must be an array of three to six terms` against closure's
`invalid indexed formula`. A check that reads the JSON before Core does avoids this only if it repeats closure's whole
traversal and fault order up to the atom. That check is closure's decoder again, so it saves nothing.

So an exact switch has to change Core's decoder: Core's formula and trace decoders gain an atom-free mode. This is the
case the 11-09 decision names ("Core's decoder gains an atom-free mode that has its own approved statement"), and it
needs a new DRI decision.

### 2.1 (a) The replacement statements, in Lean (`switch.lean` parts B and C; not in the tree)

Part B writes out the switch: `decodeFormulaWith (atoms : Bool)` and `decodeTraceWith (atoms : Bool)` (copies of Core's
decoders with one guard, `unless atoms do throw "invalid indexed formula"`), `unembedFormula`/`unembedTrace`/
`unembedTraces` (Core syntax read back into closure's), and `decodeClosureTraceViaCore`, the replacement:

```lean
def decodeClosureTraceViaCore (fuel : Nat) (j : Json) : Except String VE.Closure.Tableau.Trace := do
  unembedTrace (← decodeTraceWith false fuel j)
```

Trusted statements (what a reviewer must read to accept the switch):

```lean
/-- TRUSTED STATEMENT 1: the switch changes nothing closure answers, refusal texts included. -/
theorem switch_eq (fuel : Nat) (j : Json) :
    decodeClosureTraceViaCore fuel j = VE.CertificateWire.decodeClosureTrace fuel j
/-- TRUSTED STATEMENT 2: Core's formula decoder is the flag's `true` instance. -/
theorem core_unchanged_formula (n : Nat) (j : Json) :
    decodeFormulaWith true n j = VE.Core.Bridge.decodeFormula n j
/-- TRUSTED STATEMENT 3: Core's trace decoder is the flag's `true` instance. -/
theorem core_unchanged_trace (fuel : Nat) (j : Json) :
    decodeTraceWith true fuel j = VE.Core.Wire.decodeTrace fuel j
```

`switch_eq` is an equality of `Except String` values, so it fixes the value and the refusal text on every input.
That includes the fault order (which fault is reported first). The limits agree: Core's `VE.Limits.maxDepth`
and `maxNodes` are `abbrev`s for 64 and 10,000, closure's literals. `extraRule` is Core's by `abbrev`.

Spot check: `switch.lean` evaluates `decodeClosureTraceViaCore` against `decodeClosureTrace` with `#guard` on 10
inputs: atom node, bad node, atom then bad, binary atom, unary invariant, bad `at` before an atom, and four nested
cases. All print the same answer. This is evidence, not a proof.

**Where `switch_eq` can live.** Its right-hand side is the decoder the switch deletes. The decider has two ways:
(i) keep the old decoder as the statement's reference, so its 27 lines stay read and nothing is saved; or (ii) prove
`switch_eq` in the switching commit as one-time evidence, then delete it with the old decoder. Under (ii) the tree
keeps only the new code (section 2.2), and the refusal-path guarantee lives in history.

## 4. Recommendation (deliverable 4; the decision is the decider's)

Keep closure's trace decoder. Deleting it saves 27 trusted D[V] lines (K 0, S 0) and 28 kernel lines (measured). A
switch with Core's decoder unchanged and a check after it cannot keep closure's fault order (`no_check_after_core`,
proved). An exact switch therefore has to change Core's decoder, which the `route`, `norms`, `softNorms` and
`metered` kernel paths all read. That smallest exact switch adds back 31 trusted code lines (net +4), 9 trusted
statement lines, and audited proofs of 9 measured plus 115–239 ESTIMATE lines. The kernel moves by +1 (ESTIMATE).
Its guarantee `switch_eq` either keeps the old decoder as its reference (no saving) or survives only as evidence in
history. The trust base would not shrink, and the refusal path would depend on a new Core mode instead of code that
exists and is tested today.

If the decider still wants the 27 trusted lines out of the count, see the second note below for a route that leaves
Core and the refusal path alone.
