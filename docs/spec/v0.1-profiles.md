# VE v0.1: closure and integer order profiles

Design proposal with implementation status identified separately below; design
obligations are not claims of completed proofs. This extends
[v0](v0-language.md), following Phase V (now [ROADMAP.md](../../ROADMAP.md) section 5),
[views](../rendering-views.md), and [metatheory](../../lean/METATHEORY.md).
The [coverage ledger](v0.1-coverage.md) pins the second-rater evidence and lists
every projected mover, translation obligation, and numeric candidate decision.

## A. `closure@0`

Retain every v0 constructor. Add `Reach(k,e,t,u)`, with `k = plus | star` and
`e = Named(r) | Body(s,φ)`. Named requires `r:s×s`; endpoints have sort `s`.
Body has context `s :: s :: Γ`: index 0 is destination, index 1 source;
endpoints are checked in Γ. The two local variables bind only φ; outer
parameters remain fixed throughout a path. Nested closures are structural,
never recursive definitions. Heterogeneous hierarchies use one entity sort
with unary type predicates. Closure cannot range over the built-in numeric sort.

For valuation ρ let `R(a,b)=⟦φ⟧(b::a::ρ)` (or the named relation).
Define `R⁺ = μX.(R ∪ R;X)` and `R* = μX.(Id ∪ R;X)` in the complete lattice
of binary relations, with `(R;X)(a,c) := ∃b, R(a,b) ∧ X(b,c)`.
These monotone operators have the indicated least fixed points: unions of
finite paths of respectively positive and nonnegative length, even over
infinite structures. No infinite-length path establishes reachability.
`Reach` tests membership of the endpoint denotations. All other Tarski clauses,
including empty user sorts, remain unchanged. `R⁺` can contain `(a,a)` on a
cycle; “positive-length” does **not** mean “irreflexive.”

Strict additions (metavariables are not literal text):

```text
tc[r](t, u)                         rtc[r](t, u)
tc[s a, b | (φ)](t, u)             rtc[s a, b | (φ)](t, u)
```

`tc` means plus; `rtc` means star. Brackets, spaces, comma, bar and parentheses
are mandatory; v0 statement framing remains period+LF. The lookahead `tc[` /
`rtc[` is distinct from a v0 variable or predicate: these are contextual
tokens, not new globally reserved identifiers. No shadowing. Named and Body
are distinct AST forms, never silently interconverted. Wire tags are
`["reach",k,e,t,u]`, with `e=["named",r]` or `["body",s,φ]`.

All five views preserve source→destination:

| View | Named plus example |
|---|---|
| `fol_symbols` | `owns⁺(t, u)` |
| `fol_keywords` | `tc[owns](t, u)` |
| `ve_strict` | `tc[owns](t, u)` |
| `ve_natural` | `u is reachable from t by one or more owns steps` |
| `ve_fluent` | `S is reachable from T by one or more owns steps` |

Star substitutes `*`/`rtc`/“zero or more”, respectively. Here owns must have
homogeneous argument sorts; the v0 person→service example is ineligible.
For Body, symbols use `(TC a:s,b:s.(φ))(t,u)` / `RTC`; keywords and strict
use the strict addition with their recursive body view. Natural/fluent use
`u is reachable from t by one or more steps satisfying [s a, b | (φ)]`,
substituting their own binder names and body view. Local declarations always
retain both names. The legend defines a step from `a` to `b` and shows the raw
relation ID; arbitrary predicate prose cannot rename the reachability operator.
“From” identifies the second displayed term as source. Never emit “connected”,
“indirectly owns”, or “irreflexively reachable”. New atoms cannot become fluent
relative guards. Negation uses the existing explicit grouped fallback.
Collision filtering must include these new phrases; inverse-renderer tests
must recover the exact edge variant and direction.

Canonical printing allocates Body binders source then destination in preorder,
restores the outer scope for endpoints, and retains both edge variants.
Extend substitution, shifting, typing, P4/P5 and printer injectivity accordingly.
Grammar export adds two-binder context transitions and profile-specific atoms;
full mode enforces homogeneous sorts and endpoint scope. Syntax mode remains
an overapproximation, never a typing certificate.

Finite evaluation first computes the body relation for all `n²` endpoint pairs
per outer valuation, then Warshall: `O(n² Cφ+n³)` time, `O(n²)` matrix space,
plus body evaluation. Star initializes identity; plus does not. Cycles still
produce positive diagonal entries. Cache keys include outer parameters and
model identity. Countermodel search must recompute closure from base relations;
guessing an unconstrained “reachable” table is unsound. Bounded search failure
means unknown, and infinite structures remain part of entailment.

**Entailment design.** These are the intended schemas. The implementation
status table below distinguishes executable rules from designs. Unfolding is
usable in either polarity through ordinary signed Boolean/quantifier expansion:

```text
R*(a,b) ↔ a=b ∨ R⁺(a,b)
R⁺(a,b) ↔ R(a,b) ∨ ∃z.(R(a,z) ∧ R⁺(z,b))
R*(a,b) ↔ a=b ∨ ∃z.(R(a,z) ∧ R*(z,b))
```

Also admit edge inclusion `R⊆R⁺⊆R*`, star reflexivity, transitivity of each
closure, and monotonicity `R⊆Q ⇒ Rᵏ⊆Qᵏ`. Monotonicity requires a checked
universally quantified inclusion under the same ambient assumptions and
parameters, never just observed edges. These are induction-free *search rules*;
their metatheorems use finite-path induction. Version `ve-tableau-closure-checker@1`
also admits a supplied unary invariant: `P(x)` and
`forall a,b. (P(a) and R(a,b) -> P(b))` entail
`forall y. (Rᵏ(x,y) -> P(y))`, for plus or star. Both obligations require
certificate subproofs. No cyclic proof acceptance or “saturated means satisfiable” rule is added.
Unfolding alone does not characterize the least fixed point.
Existing equality congruence extends to closure endpoints and captured
parameters; it never identifies different edge ASTs without a checked lemma.

Implementation status for `closure@0` (2026-09-22):

| Schema | Status |
|---|---|
| `R* ↔ Eq ∨ R+` | Implemented as `closure-star@0`, both polarities; Lean proved. |
| `R+ ↔ R ∨ exists (R ∧ R+)` | Implemented as `closure-plus@0`, both polarities, Named and Body; capture-safe substitution proved in Lean. |
| Direct recursive star unfolding `Eq ∨ exists (R ∧ R*)` | Designed; no separate replay rule. |
| Edge inclusion | `closure-edge@0` for homogeneous Named binary edges; Body edge inclusion can use unfolding. |
| Plus-to-star inclusion and star reflexivity | Implemented through star unfolding and ordinary signed/equality rules. |
| Path composition | `closure-compose@0`, all four plus/star combinations; exact same edge AST, captured bindings and middle term. Lean proved. |
| First/last-edge existence | `closure-first@0`, `closure-last@0`, positive plus only, Named and Body. Lean proved. |

| Supplied-invariant induction | `closure-induct@1`, Named and Body, plus and star; Lean soundness proved and Python/Lean differential replay. |
| Monotonicity under universal inclusion | T9/T9e now certify through induction with supplied invariants and checked preservation subproofs. No inclusion oracle; search without hints retains its ResourceLimit regression. |

| Arithmetic induction/cyclic acceptance/saturation completeness | Not implemented or accepted. |

Every implemented addition has a Lean branch-soundness proof before its Python
replay mirror. Search composes existing paths and includes edges; existential
consequences and Named conversion are selected when they connect to the goal.
Replay reconstructs the result from indices; no submitted derived AST is trusted.
New certificates use `ve-tableau-closure-checker@1`; existing `@0` certificates
are accepted unchanged, with induction disabled for that version. Distinct rule
tags retain their previous meanings. `VE.Closure.Tableau.checkCertificate_sound` proves acceptance implies
extended `Entails` over every admissible structure, and
`checkCertificate_sound_v0` specializes through denotation conservativity.
The original v0 checker and theorem statement remain unchanged.

Finite, effectively checked certificates cannot be sound and complete for
general standard TC validity, stronger than mere undecidability; see
[Lev-Ami et al., Proposition 4.1](https://people.cs.umass.edu/~immerman/pub/SimulatingReachability.pdf).
Implemented certificates record versioned rule tags and exact signed parent
indices (a second index in `parameter` for composition). Original inputs bind
edge/body ASTs; replay computes substitutions and fresh witnesses. Inclusion
subproofs can be discharged in the induction preservation branch. Replay reconstructs
children; a submitted rule name is not evidence. Bind environment, ordered
premises, conclusion and checker version. Lean needs closure denotation,
substitution lemmas, each schema's soundness, branch-satisfiability preservation,
and `CertificateSound` for graph composition, plus finite Warshall correctness
and `eval_iff_denote`. Existing v0 proofs do not establish these obligations.

**Examples and attacks.** Cedar sample `policies_3a.cedar#0` permits `view`
when the resource is in `Album::"jane_vacation"`. Reify request `q` with
`request_action(q,a)` and `request_resource(q,r)`; its matching condition is
`a=@view ∧ rtc[parent](r,@album)`. `parent` points child→parent. Two parent
edges match; the album itself matches; reversing the edges need not match.
Include referenced but unloaded entity IDs so equality still works; preserve
missing attributes and exceptions in other policies. This is one policy's
contribution, not the final authorization decision.
[Cedar specifies reflexive hierarchy membership](https://docs.cedarpolicy.com/policies/syntax-operators.html).

Alloy sample `chord2.als@81`, `j in i.^(Id<:next - Id->from)`, becomes
`tc[id a, b | ((a next b) and (not (b equals from)))](i, j)` within the three
parameter binders. This deletes edges **into** `from`; it does not delete
outgoing edges. The duplicate `chord.als@80` remains a separate sampled item.
[Alloy defines least transitive closure](https://alloytools.org/spec.html).
Experiment pairs swap closure/one edge, star/plus on an isolated vertex,
source/destination on a directed chain, and plus/“unequal endpoints” on a cycle;
also attack filter scope and outer-parameter capture.

## B. `order@0`: linear integer arithmetic

**Implementation checkpoint (2026-09-21):** the separate Lean foundation now
implements integer arithmetic with **integer quantification disallowed**, and
order/closure composition is **not implemented**. Order-only and combined
order/closure certificate envelopes remain rejected by the existing gate. Python integration, order conformance and witnesses
are pending. The full design below, including Presburger evaluation and its
coverage projection, is not a claim about that narrower executable fragment.
See [the implementation boundary](order-implementation.md) and
[exact proved statements](../../lean/ORDER.md).

Choose candidate 3, standard ℤ with linear expressions. Candidate counts are
whole-item fits out of the **45 numeric-gap items**, retaining reification:

| Candidate | Numeric obstacle discharged | Whole items newly fit |
|---|---:|---:|
| 1. Integer constants and `<, ≤, =` | 9 | 5 |
| 2. Also constant offsets / difference logic | 9 | 5 |
| 3. Linear integer arithmetic | 18 | 14 |

The ledger lists all 45 decisions. Candidate 2 adds no full item: structural
last-position reification already handles `online_max`; HPA's bound is a
**variable** minimum spread, not a literal difference bound. Candidate 3 is
the smallest listed choice capturing that rule, pair sums, tripling, doubling
and parity. Parity is `∃q:ℤ, x=2q`, without a primitive modulo operator.

None captures the 18 FRET gaps: these involve real-valued signals, sometimes
also metric time or trigonometry. FOLIO's score granularity is unspecified.
Do not count either by integerizing values. Dense and discrete orders are
different semantics; “numeric” is not permission to choose either silently.
A real-number profile remains separate future work. Variable products,
variable-divisor modulo, and general counting are excluded.

Add built-in sort `$int`, distinct from every user identifier, interpreted
as standard ℤ in **every** structure. Add typed terms `Num(z)`, `Add(t,u)`,
`Scale(z,t)`, and formulas `Lt(t,u)`, `Le(t,u)`; equality reuses Eq. Operands
are `$int`; numeric terms may occupy predicate arguments of that sort.
Quantifiers range over all ℤ. Denotation uses ordinary integer addition,
literal multiplication, comparison and equality; no overflow or coercions.
Wire tags `num`, `add`, `scale`, `lt`, `le` follow those argument orders;
signed coefficients/numerals are canonical decimal **strings**, avoiding JSON
precision loss. Uninterpreted numeric constants may alias; distinct numerals cannot.

```text
#0    #-12    add(x, #3)    scale(#-2, x)
x < y    x <= y    x equals y
for every $int x, (x < add(x, #1)).
```

Decimal grammar is `0 | -?[1-9][0-9]*`: no plus sign, leading zero, negative
zero, decimal point or exponent. `add(`/`scale(` are contextual tokens;
scale's first argument must be a numeral. No implicit precedence.

| View | Example, with integer operands |
|---|---|
| `fol_symbols` | `x < (y + 3)` |
| `fol_keywords` | `x < add(y, #3)` |
| `ve_strict` | `x < add(y, #3)` |
| `ve_natural` | `x is less than (the sum of y and 3)` |
| `ve_fluent` | `I is less than (the sum of I2 and 3)` |

Le uses `≤`/`<=`/“is at most”; Eq retains each view's equality wording.
Scale uses `(z × t)`/`scale(#z,t)`/`(z times t)`; Add uses the displayed
sum form. Numeric quantifiers say “integer”; constants retain `@`.
Preserve term trees and grouping, never algebraically normalize identity.
Grammar export tracks numeric term depth/size, coefficient digits and sort;
canonical printing preserves literal values. Grammar budgets are explicit
generation limits, not semantic integer bounds.

**Evaluation and entailment.** An order model is a *finite presentation*,
not a finite integer domain: finite user sorts and complete finite predicate
tables, with numeric cells storing actual integers and `$int` implicit.
Use canonical signed decimal strings for numeric model cells and constants;
their declared argument sorts distinguish them from user-sort entity IDs.
Absent tuples are false, including outside listed integers. Reject a supplied
finite `$int` enumeration. Expand user-sort quantifiers and finite predicate
tables into a Presburger formula; decide it by integer quantifier elimination.
Combined closure uses symbolic Warshall over finite user sorts. This gives a
total reference evaluator; budgeted implementations may return unknown.
Ground arithmetic costs polynomial bit operations; `q` finite binders can
produce `n^q` instances. Quantifier-free integer feasibility is NP-complete;
quantifier elimination can multiply formula size repeatedly. No polynomial
whole-document cost is promised.

Tableau arithmetic leaves go to an untrusted LIA/SMT prover. Acceptance requires
a kernel-checked Lean proof of the exact leaf contradiction over `Int`, with
all branch assumptions and equality substitutions bound. A proof-producing
[Lean arithmetic tactic](https://lean-lang.org/doc/api/Lean/Elab/Tactic/Omega.html)
is an initial implementation route; SMT `unsat` alone is never accepted.
Replay generates the expected theorem type independently and audits logical
dependencies; a certificate-supplied proposition, `sorry`, or added axiom fails.
Allow checked linear combinations, integer rounding/cuts and exhaustive integer
case splits, or equivalent proof terms. Rational infeasibility alone misses
integer contradictions such as `2x=1`. Prover failure is unknown. Pure
Presburger arithmetic is decidable; arbitrary relational FOL plus arithmetic
does not thereby become decidable.

Lean first proves integer term denotation/substitution, arithmetic certificate
soundness, and finite-presentation reduction/evaluator correctness. Search
enumerates bounded object domains and integer assignments, then rechecks the
entire candidate over ℤ, including quantifiers. Bounding candidate values
never bounds their meaning. Failure to find a counterexample means unknown.
Attack pairs change `<`/`<=`, coefficient sign, offset, units, integer/real
interpretation, or replace an all-integer quantifier with an active-domain loop.

For sampled HPA, the spread test is `add(min, spread) <= max` after explicit
field lookup; `spread` remains a variable. For Clover `triple`, the contract is
`@output equals scale(#3, @input)` for one invocation. Neither example asserts
the implementation satisfies its contract; it makes the contract checkable.

## C. Strings: adapter boundary

For the 20 string/regex Gatekeeper gaps, specify an external deterministic
function `F_version(input_bytes, parameters) -> result | error`, pinning regex
dialect, Unicode/case rules, splitting, concatenation, parsing and error behavior.
Reify calls/results as typed finite relations. Provenance binds input hashes,
function specification/implementation versions, parameters and output hash;
check total call coverage, tuple types, uniqueness and explicit error records.
Trusted recomputation or a separate verified certificate establishes correspondence
to F; provenance alone does not. VE checks formulas over the submitted relation,
not regex correctness, source completeness, universal behavior on unseen strings,
or the external implementation. Preserve exemption and serialization-collision
behavior. No string-adapter coverage is credited to A/B.

## D. Compatibility and implementation order

Both are conservative extensions of `relational-fol@0`: every old structure
has an expansion, with identical truth for old formulas. Old bytes,
environments, renderers and identity preimages stay valid unchanged. Opt-in
v0.1 environments use `language: ve.core@0.1` and sorted unique `profiles`
containing `relational-fol@0` and either/both additions, replacing singular
`profile` only in this new envelope. Bind the complete list and revision in
new v0.1 identity domains. No automatic migration; unknown versions fail.

Estimated person-weeks, including review; these are planning judgments:

| Order | Component and required work | Effort |
|---|---|---:|
| 1 | Lean AST, denotation, conservative embedding, binding, closure/Int lemmas | 2–3 |
| 2 | Lean finite evaluators, certificates, P4/P5/P10/P11 extensions | 3–5 |
| 3 | Python wire/parser/checker, numeric model format, search, replay | 1–2 |
| 4 | Rust matching types, big integers, evaluation and conformance | 1–2 |
| 5 | Five views/inverses, legends, grammar exporters, numeric budgets | 1–2 |
| 6 | Oracle routing, cache/profile bindings, adapter provenance, attacks | 1–2 |

Total 9–16 person-weeks. Semantic proofs precede runtime integration; full
integer evaluation may dominate. Require shared empty/cyclic/directional graph,
parameter-scope, negative/large-integer, infinite-integer-quantifier and forged
certificate cases. Existing metatheory gaps remain explicitly open.
