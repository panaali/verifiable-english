**Why one rule over the rows and not one rule per row.** PLAN 12 item 2 records that "A constant cannot fill an act's
slot". So the row rules are one rule per reading over every listed threshold, with the row as the act's parameter.
The task names this shape as the faithful merge within the cap ("one act with a row parameter, as the generic rule has
today"). `listed` holds for exactly T1-T4 (facts.d1.ve threshold-t1..t4), so the one rule requires what four row rules
would. The rule text is unchanged, and the row content lives in the act's legend.

There was also a second reason not to add blocks. A per-row block layout would have moved the 76-block pin of
tests/data/norm-blocks/rsp.jsonl. That would have changed tests/test_english_statement_blocks.py, capture_blocks.py
and en-2's saved Lean-shadow delta.json, which is another item's evidence. The conservative option was taken, as
standing override 2 asks, and no DRI question was sent.

Seeded bug (a) is therefore "the base's generic pointer legend back" and not "the generic rule text back", because
the rule text did not change.
