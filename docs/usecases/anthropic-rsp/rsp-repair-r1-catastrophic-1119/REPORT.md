**Where the legend lives, and why.** The risk wire's `severity` block is
`{sort, classes, more_severe, unranked, decided_by}`, and `classes` is a list of names (`lean/VE/Risk/Wire.lean:200-206`,
`exactFields`). So the class "catastrophic" has no description field of its own. Adding one would be a Lean change,
which is out of scope. D2's environment legend for the class is therefore the description of footnote 1's own constant,
`existential_threats`. D2 classes that constant `catastrophic` (`risk.harm_classes`), and S5 rests on it. Its old
description quoted only the footnote's "such as ..." clause. The text sits in `stage0.py` code that `d2()` sends to
the risk route. Under the carrier guard (converge-AB.md section 0) it is a code run in the D2/D3 unit
(uc-audit.py.reads-1119 line 670: "stage0.py (d2(): the D2 risk@0 document ...)"). It is not a header or a citation,
and not a bare constant table such as LEVELS, which is a list of names. The prefix `footnote 1 (the catastrophic class,
verbatim):` is a label, and the footnote text follows it as a whole run.

`docs/usecases/safetyfw/anthropic-rsp/stage0.json` was regenerated with `uv run python usecases/anthropic-rsp/stage0.py`.
Before that, `--check` printed "stage0.json is out of date". The diff is one line: D2's `environment_id`, because the id
hashes the description. D2's `admitted`, its classes, its 16 might cells and its 0 leads cells did not change.
