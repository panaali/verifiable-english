
## Conflict C1 (as reported in README): F16 against F15
VE finds a witness when three readings hold together: RS3 = Ds (the recommendation binds the developer), RS3force = strict, and RS6 = same (F15's "additional mitigations" are the same act as Security Level 2+'s insider-threat measures). Witness: a model at CBRN uplift level 1, further development. Rules in conflict:
- f16-ds-strict: Every proposal must apply each measure to the model weights, if there is a level such that all of the following hold: (a) that proposal has reached that level; (b) at least one of the following holds: (i) that level recommends that measure; (ii) there is a second measure such that both that level recommends the second measure and the second measure includes that measure, unless [like_public_models, security_assessed_adequate or open_release_benefits_outweigh_risks].
- f15-same: Every proposal need not apply each measure to the model weights, if all of the following hold: (a) there is a level such that both that proposal has reached that level and that level is misuse; (b) that measure addresses insiders.
- premise: "security_level_2_plus" includes "insider_threat_measures"; "insider_threat_measures" addresses insiders; cbrn_uplift_level_1 recommends security_level_2_plus.
Source:
> [s211-sl2plus] We also define and recommend "Security Level 2+," which uses RAND Security Level 2 (SL2) as a baseline, with additional security measures designed to address risks from insider threats and well-resourced non-state external actors.
> [s22-insider-assessment] While we monitor for potential future risks related to insider misuse, our current assessment of these risk domains indicates that the risks of insider misuse posed by the misuse T/CCLs identified below are effectively addressed by our baseline controls (such as background checks and access restrictions).
> [s22-insider-not-required] At this stage, additional mitigations beyond these established safeguards are not required.
> [s22-recommend] We recommend a security level for each CCL, which reflects our assessment of the minimum appropriate level of security the field of frontier AI should apply to models reaching each CCL.
> [s22-adjusted] These recommended security levels reflect our current thinking proportionate to the risks posed and may be adjusted if our understanding of the risks changes. This may occur if, for example, a model does not possess capabilities meaningfully different from other publicly available models that have weaker security applied (in which case the marginal benefit of higher security is limited), or if we assess that the benefits of the open release of model weights outweigh the risks.

## Conflict C3 (as reported in README): F9 bullet 2 against F10 bullet 3
Reported when RS1 = G (the conditions are a gate), RS8 = rel ("not internal deployment" is a release), RS9 = same (both bullets' deployment-mitigation conditions are one act). Witness: a model that has reached both a misuse CCL and an ML R&D CCL, proposed for high-risk internal deployment. Rules in conflict:
- f9-rel: Every proposal need not have mitigations make the residual risk of harm acceptable, if (a) either that proposal is internal or that proposal is classified as "further_development"; (b) there is a level such that that proposal has reached that level and that level is misuse.
- f10-dm-same: Every proposal must have mitigations make the residual risk of harm acceptable, if (a) either that proposal is external or that proposal is classified as "high_risk"; (b) there is a level reached that is critical and ML R&D and misalignment.
Source:
