# North Star: every document the lead cares about

VE should express every kind of document the lead cares about, with Claude's constitution the lead's main use case. Ultimately **VE's own paper and documentation website must be written in VE**, including the tutorial, explanations, examples and user-facing web copy. Textbooks are a future target.

Success means preserving the document's meaning in readable VE, with checked structure, explicit readings and named residual judgments. Authoring may choose intended readings and record those choices; translation must preserve unresolved alternatives. Labelling text, retaining it verbatim or parsing a sentence does not by itself establish faithful semantic coverage.

Snapshot: **2026-09-27**, repository baseline `9db5a20` (`ve-integration` / this worktree). Latest full-document pilots: `run-20260927T1800Z`, language baseline `ve-green-flaky`. External evidence below lives in sibling worktrees and `~/code/manage-agents` (`M`); it is not vendored here.

**Ranking rule:** estimated weighted unlock = Σ(weight × estimated newly expressible source bytes / that use case's source bytes). Normalising by document size keeps a long document from winning purely by length. The estimates below are **0–upper-bound byte opportunities**, derived from primary-blocker spans in the [C ledger][c-units] and [U ledger][u-units], conditional on resolving co-blockers and fidelity review. Unmeasured use cases contribute **unknown**, not zero; ranks are provisional. Presupposition's 999 B is removed from discourse's 8,200 B to avoid double counting here. Do not sum potential gains across features.

Status is relative to `9db5a20`: **merged** = present there, **building** = implementation branch exists but is unmerged, **planned** = documented work, **not started** = no implementation/design evidence found. Dependencies below are implementation needs, not claims of completed semantics.

## Next three features to start

Soft norms are already building: finish their integration and rerun C first. Start the next three ranked features with these bounded deliverables:

1. **Rights / claim-rights:** design holder–duty-bearer readings for UDHR clauses, sharing W1 and soft-norm elaboration; preserve ambiguity and open legal standards.
2. **Quantities/units and graded comparisons:** implement the planned W6 decimal/unit slice against the news cases, and separate C's numerical claims from vague comparisons before claiming any C unlock.
3. **Causation / preventable harm:** design a minimal Asimov inaction case with explicit alternatives and time; establish which causal/evidence assumptions stay open, then test against C/U clauses.

These are a proposed start order, not implementation or byte-gain commitments.

## Refresh contract

- **After every pilot run:** read that run's `metrics.json`, `units.json`, `AUDIT.md` and `TREND.md`; record source hash, language commit, denominator, status bytes/units, admitted readings, residuals and audit basis. Reconcile sums and spans. Compare byte deltas on identical sources; keep old-boundary aggregation when units split. Distinguish new semantics from audit repairs and relabelling.
- **After every merged feature:** verify ancestry/status, rerun affected local checker/coverage workflows, refresh the portfolio and recompute the weighted estimates from tagged spans. Keep measured coverage unchanged until a new measurement supports it; record co-blockers and avoid double counting. Do not silently turn legacy totals or sampled audits into byte coverage.
- **Pending measurements:** consume `M/codex-bluedot.final.md` and `M/codex-webapp-allve.final.md` when present, following their linked artifacts. Inventory and pin V/D sources next; estimate unknown rows only after their ledgers exist. Revisit weights with the lead and rerank; record dates and reasons. This refresh requires no model calls.
