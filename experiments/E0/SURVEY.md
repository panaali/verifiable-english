# E0/E1 dataset survey

Date: 2026-09-21. Target fragment: VE v0 (`relational-fol@0`): many-sorted, function-free FOL with equality, unary/binary predicates, constants, closed formulas, no arithmetic, no subtyping.

**Status: exploratory.** Every a/b/c/d label below comes from one model rater. Until a second rater from the other model family has labelled the same samples and agreement is reported, none of these shares should be cited as a result.

**How to read the numbers.** For each dataset, 30 items were drawn with `random.Random(20260921).sample` over the id-sorted population (`survey_sample.py sample`). Every sampled item was read and classified by a model reader (Claude), not a human; no second rater, no agreement statistic. With n=30 a reported share has roughly +/-15-18 points of sampling error. "Mechanical" numbers are regex checks over the full dataset (`survey_sample.py mechanical`); they detect surface constructs only and are reported separately. Per-item labels and reasons: `survey_samples/<dataset>.jsonl`. Reproduce the mechanical numbers with `uv run --with pyarrow python experiments/E0/survey_sample.py mechanical` after re-downloading per `data/README.md`; Worker C re-ran this and the FOLIO and ProofWriter figures matched. The a/b/c/d labels were entered by hand and are not regenerated by the script.

Classes: **a** direct fit; **b** fits after mechanical reification (n-ary -> event entity, function/attribute -> relation is counted as a, record/request/time-point reification and sort assignment as b); **c** fits only through opaque predicates hiding arithmetic, numeric comparison, string matching, cardinality, closure, or metric time; **d** no fit (second-order, or nothing but an arithmetic equation).

## Per-dataset notes

**FOLIO.** Item = one NL sentence with its gold FOL. Mapping: gold FOL is unsorted, so v0 needs a sort assignment (one `entity` sort works; better sorts need per-story work). Predicates map one-to-one; XOR expands to and/or/not. Misfits are ternary event predicates (mechanical reification) and numeric facts hidden in names such as `GreaterThan95`. Gold quality is uneven: in the sample, one gold formula has a free variable, one collapses "a coffeemaker and a blender" into one predicate, several drop temporal qualifiers. E1 pair: (NL premise, gold FOL rendered as VE) as the matching case; mismatches produced by controlled perturbation (swap quantifier, drop conjunct, flip argument order). Ground truth: expert annotation, but noisy enough that some "mismatch" verdicts by a judge will be correct. Contamination: high; public since 2022 with FOL annotations.

**ProofWriter.** Item = theory + question. Single sort; unary (Att*) or unary+binary (Rel*) predicates; named individuals as constants; rules are universally quantified implications, some with negated literals. Every sampled item fits directly. Caveats: (1) the mirror contains only OWA variants; CWA variants (negation as failure) would not match v0's classical open-world entailment and should be excluded anyway. (2) To my understanding the OWA labels come from a forward-chaining rule engine, so "Unknown" may disagree with classical entailment (contraposition, case reasoning, inconsistent theories). I did not verify this; labels must be recomputed with a prover before use. (3) The mirror lacks the original logical-form fields, so formalizations must be regenerated from the templated English (deterministic for the non-NatLang configs). Language is synthetic, so coverage here says little about real requirements. Contamination: high for the distribution, lower for individual theories.

**Cedar.** Item = one policy. Mapping: entity types -> sorts; attributes -> binary relations; boolean attributes -> unary; `in` -> a supplied binary membership/ancestor relation (its transitive closure is computed by the model adapter, not by v0); a policy -> "for every principal, resource: if conditions then permitted_<action>". Reification is needed when the action is quantified or `context` is used (request entity), for record-valued attributes, for templates (instantiate slots), and where a set mixes entity types (no subtyping -> union sort). Class c is rare (IP/decimal/datetime extensions, numeric comparison). Permit/forbid override and default-deny are policy-set semantics outside a single formula. E1 pair: many example policies carry a prose comment or README sentence stating intent (my splitter strips comments; keep them for E1). Ground truth: Cedar's own authorizer on the test requests in cedar-integration-tests gives executable ground truth for model evaluation. Contamination: moderate (public repos, small, but no formalization into FOL exists online). Only 143 items.

**Gatekeeper/Rego.** Item = one constraint template. JSON objects -> entities, fields -> relations. About half the sample depends on string prefix/regex/glob, unit parsing or numeric ranges (class c). Of the 14 a/b items, 7 also call `is_exempt`, which glob-matches image names; I classified by the core rule and flagged this in the reason field. Counting those as c gives 7 a/b of 30. Each template has a prose description in `constraint.tmpl` and test fixtures with expected violations: good E1 prose and executable ground truth, but poor v0 fit.

**Alloy.** Item = one fact/assert/pred paragraph. Relational, but most models use ternary (state/time-indexed) fields -> reification; signature hierarchies -> unary predicates over a parent sort; `pred`s with parameters are open formulas and must be closed or inlined (v0 has no definitions). Closure, cardinality and `util/ordering` arithmetic push a third of the sample to c; quantification over relations is d. Prose is sparse (comments only), so E1 pairs would need to be written. Ground truth: the Alloy Analyzer on bounded scopes.

**Clover (Dafny).** Specs are integer/array arithmetic. Only pure-equality swaps fit. Not useful for v0 beyond being an honest negative for E0.

**FRET.** Every requirement is temporal; `always` and simple triggers reify to a time-point sort (b), but 22/30 sampled items need numeric comparison, arithmetic or metric time. The FRETish text is already controlled language, not free prose.

## Recommendation

**E0 (coverage).** Report a spread rather than one number: (1) Cedar and (2) Gatekeeper as the real-world policy sets (expected: Cedar mostly a/b, Gatekeeper about half c); (3) FOLIO as the natural-language reasoning set, using the mechanical 91.6%/76.3% figures plus hand audit; (4) Alloy, FRET and Clover as boundary sets that show where v0 stops (closure, time, arithmetic). ProofWriter is a ceiling check only: 100% fit by construction.

**E1 (weak judge on prose vs formalization).** (1) FOLIO sentence pairs restricted to mechanically clean formulas, with perturbation-generated mismatches and a manual audit of gold quality; treat scores as contaminated upper bounds. (2) Cedar policies with their prose comments: small, but realistic, low contamination for the VE rendering, and executable ground truth. (3) ProofWriter non-NatLang theories as a sanity floor where the formalization is unambiguous. Gatekeeper is attractive for prose quality but most items would need opaque predicates, which is exactly what E1 should not reward.
