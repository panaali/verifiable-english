## Wording and proposed fixes for review

1. The v5 rule “a step derived from a reason the sentence does not give, directly or through a helper, is unfaithful” drives `#34`. Refine it to distinguish a *source claim's stated reason* from an attempted, checker-refuted proof's surplus given rule. If the conclusion and stated reason are represented and an extra given edge contributes no established premise, ask the auditor to flag it for spot-check without failing fidelity. Keep failure when an added premise actually changes or establishes the asserted result, when the stated reason is absent (`#24`), or when a helper asserts a new fact. Review this with the gap-route rule so a refuted step is not required to have a valid proof for a faithful-complete gap.
2. Keep the v5 omission and waiver rule: “an omitted sentence with no code is unacceptable” and “unacceptable if it asserts something the stated reasoning relies on.” It caught real losses. Clarify that *“checks remain unassumed”* may be waived under `unassumed`, whereas *“checks would imply/establish X”* is an expressible claimed conditional and cannot be waived merely because the checks are unassumed. This prevents the old pass from returning through a loose waiver interpretation.
3. No code or prompt was changed here. Prompt/rule edits require review and a fresh DEV audit before freeze; this saved proxy alone does not establish held-out performance.
